# C3 1.3.0 stable plan

Planned tag: `v1.3.0`

Stable is a final qualification and publication operation, not another feature
milestone.

Stable publishes exactly the three lanes in the
[ratified matrix](../governance/1.3.0-three-lane-matrix-2026-08-05.md). No C3
installer or updater is part of this release.

## Entrance

- Beta 1 is feature complete, compatibility complete, and owner accepted;
- no unresolved S0–S2 defect exists;
- every supported OS/lane claim has direct evidence;
- the licence decision for redistributed package contents is recorded; and
- the exact accepted Beta source is frozen.

## Stable source transition

Create one direct metadata-only commit from the accepted Beta source. It may
change product stage/date, changelog, release notes, and package labels. It must
not change behaviour, dependencies, settings schema, catalogue format, resources,
manifests affecting behaviour, or payload composition.

Any functional correction returns work to a new beta checkpoint.

## Qualification

1. Update each authoritative builder to the latest stable servicing release in
   its declared family, capture one immutable external lock bound to clean
   source commit `C` and the exact remote ref, record the lock SHA-256, and
   build all three lanes twice from clean, different absolute paths.
2. Compare source manifests, output metadata, payload entries, ZIP timestamps,
   sizes, retained entry manifests, and SHA-256 values.
3. Run every automated qualification gate.
4. Run the complete manual workflow and OS matrix against retained stable bytes.
5. Confirm every package `BUILD.txt` records `C`, the external-lock SHA-256,
   compiler/reference/resource-tool hashes, and matching extracted bytes.
6. Create an evidence-only qualification commit and annotated `v1.3.0` tag.
7. Advance `legacy/1.x` only to the qualified checkpoint.

Stable bytes are newly built and requalified; Beta hashes are not reused as
stable hashes.

Required public assets are exactly:

```text
C3-v1.3.0-win-x86-net40-portable.zip
C3-v1.3.0-win-x64-net48-portable.zip
C3-v1.3.0-win-arm64-net481-portable.zip
SHA256SUMS.txt
```

The payload gate rejects MSI, MSIX, ClickOnce/bootstrapper output, installers,
uninstallers, updaters, raw standalone EXEs, runtime DLLs, and files outside the
portable allow-list.

## Publication and post-verification

1. Publish the already-qualified ZIPs and `SHA256SUMS.txt`; never rebuild.
2. Download every asset into a clean directory.
3. Verify names, sizes, hashes, ZIP entries, CPU/framework/version metadata,
   launch, and save/reopen.
4. Record success or failure without rewriting the tag or assets.
5. On success, commit post-publication evidence and update the root legacy feed
   to `1.3.0 / Release` as the final operation.
6. Fast-forward `dev/1.x` and `legacy/1.x` to the same verified checkpoint.

If post-verification fails, the feed and qualified ledger remain unchanged.
Preserve the failed evidence and create a superseding candidate.

## Closure

Archive retained packages, package-entry manifests, hashes, the external lock,
toolchain identity, validation records, and private test instructions. Freeze
1.x under the 1.3.1 emergency-only policy and move all ordinary evolution to
2.x.
