# C3 1.3.0 Alpha 5 — Legacy Layout Stabilization

Planned identity: `1.3.0a5 / Alpha 5 / v1.3.0a5`

Status: ratified and ready for implementation; release identity remains Alpha 4

Alpha 5 is the final intended owner-test preview before Beta 1 consideration.
It repairs the layout mechanism exposed by Alpha 4 without replacing the
original C3 information architecture or classic WinForms character.

## Phase 0 — normalize the legacy source tree

Status: complete. The byte-identical shared setup engine is Installer-owned,
all consumers resolve the one physical source set, and the closed topology
validator is part of the preparation gate.

Before any Designer change:

1. hash the 13 `SetupShared/*.vb` source files;
2. move them without content edits to
   `Compact Cassette Catalogue Installer/Shared/`;
3. update the two setup projects, setup tests, validators, and documentation;
4. prove both setup EXEs compile the same physical files without a DLL;
5. prove source bytes, types, and runtime behaviour are unchanged;
6. update only the exact reviewed production-path/setup-genome mappings;
7. pass setup and complete source gates; and
8. commit the topology normalization independently of UI work.

The 1.x tree then has exactly three production source roots. Root `src/` and
`SetupShared/` are absent.

## Phase 1 — reproduce before reconstruction

Replace the property-only “sizable and scroll safe” test with a fresh-process
STA geometry harness. Before fixing a form, retain a failing Alpha 4 control
tree for its known overlap, clipping, unreachable command, or dynamic-control
condition.

The first test tranche must:

- fail `frmMain` sibling overlap at reduced width;
- fail runtime static button creation and geometry mutation;
- fail the Tape New command/model geometry;
- fail each affected entity-browser layout;
- establish the matrix process/evidence schema;
- retain explicit overlay exceptions only for mutually exclusive named panels;
- add source-policy checks for prohibited handler geometry; and
- create the `UI-START-001` launch instrumentation contract without claiming a
  diagnosis.

## Phase 2 — separate policy from geometry

Retain in `CatalogueWorkflow.vb`:

- prerequisite plans and journey coordination;
- stable-key choices and selection snapshots;
- explicit creation results;
- validation issues;
- pure command/presentation state; and
- accessible-text or validation helpers that do not position controls.

Remove or reduce the geometry-oriented `CatalogueUx` methods. Move every known
static command into its form Designer. Prohibit visible-control construction
and fixed geometry mutation in production `Load`, `Shown`, and `Resize`
handlers.

Add one narrow `controlNames` genome exception for reviewed containers and
static buttons only after the exact names exist and the geometry suite covers
them.

## Phase 3 — form reconstruction

Each form/family has two commits where practical:

1. structural reparenting with default-view comparison; and
2. adaptive sizing/scrolling with focused matrix evidence.

Implementation order:

1. `frmMain` root/header/editor ownership and Designer empty state;
2. `frmTapeNew` preferred-width editor canvas and persistent command bar;
3. `frmTapes`, `frmModels`, `frmBrands`, and `frmDecks` SplitContainer family;
4. Brand and Model add/edit fixed dialogs;
5. `frmDeckNew` and `frmDeckEdit` viewport/command structure; and
6. conditional forms only when their matrix cell reproduces a defect.

Use Visual Studio 2017/net40 at 100% scaling as the canonical legacy Designer.
Do not independently resave shared Designer files in multiple Visual Studio
generations. Inspect every Designer and `.resx` diff before proceeding to the
next form.

## Phase 4 — visible text and accessibility

Audit visible captions, spelling, sentence-style capitalization, colons,
ellipses, Add/Edit/Delete/Save terminology, and access keys. Keep historical
stored keys stable when correcting display text.

For each form prove:

- reading-order tab traversal and unique tab positions;
- unique access keys per scope;
- safe initial/default focus;
- Enter for the safe default action and Esc for Cancel;
- focus restoration after prerequisite detours;
- visible selection and focus cues;
- first-error focus plus readable validation summary;
- ErrorProvider spacing;
- coherent accessible name, role, state, and bounds; and
- system-colour/High Contrast legibility.

Cancel buttons use `Text = "Cancel"`, `DialogResult.Cancel`, and the form's
`CancelButton`; they do not consume an access key.

## Phase 5 — presentation state and stability

Centralize command availability only where it replaces scattered inconsistent
state. Refresh lists with stable-key selection/focus restoration. Protect
noticeable commands against duplicate activation and restore state in
`Finally`.

Do not add persisted bounds, splitter/column state, a status strip, column
chooser, runtime font resolver, or universal DPI-awareness change merely to
finish Alpha 5. Each reopens a separate compatibility or owner-design choice.

Measure repeated form creation/close, rapid resizing, `Layout` event counts,
handles, memory, event subscription, duplicate controls, list refresh, and
first-window latency. Use `BeginUpdate`, `SuspendLayout`, or double buffering
only in response to measured behaviour.

## Phase 6 — complete qualification

Run the complete size/scale/content matrix in fresh STA processes. Retain
geometry JSON and diagnostic atlases. Then run native 100/125/150/200% display,
Windows 7 canonical, XP/classic-font, High Contrast Black/White, keyboard-only,
screen-reader, and owner visual review.

`UI-START-001` remains independently blocking until repeated x86/x64 launch
instrumentation explains or reliably rejects the process-without-window state.
Native ARM64 visual/runtime proof uses the exact target environment.

Run historical Gate 1 and exact XP, Windows 7, and native ARM64 qualification
against the final Alpha 5 bytes. Earlier Alpha/Beta Candidate bytes do not fill
these rows.

## Definition of done

Alpha 5 passes only when the original visual identity is intact; the canonical
view is approved; no matrix cell has unexpected overlap, clipping, or
unreachable actions; default views avoid unnecessary scrollbars; larger views
expose useful content; ultrawide fields remain bounded; Side A/B remain
symmetrical; static controls are Designer-owned; keyboard, High Contrast, and
assistive-technology contracts pass; repeated layout is stable; startup has no
unresolved regression; and all application/setup/package/reproduction gates
pass again.

Alpha 5 does not authorize public publication, a Beta-labelled artifact or
tag, `master`, `legacy/1.x`, `dev/2.x`, public-feed, or stable movement.
