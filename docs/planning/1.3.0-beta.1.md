# C3 1.3.0 Beta 1 plan

Planned tag: `v1.3.0b1`

Beta 1 is the promotion of the runtime-complete Alpha 3 scope. The
[6 August owner decision](../governance/1.3.0-beta1-authorization-2026-08-06.md)
authorizes retained Beta-labelled Candidate bytes now and authorizes the tag
and conditional `legacy/1.x` advancement only on a complete technical GO.

Beta 1 is governed by the
[ratified three-lane matrix](../governance/1.3.0-three-lane-matrix-2026-08-05.md),
which supersedes Alpha's four diagnostic lanes without rewriting the Alpha tag.
Its release lanes are exactly `win-x86-net40`, `win-x64-net48`, and
`win-arm64-net481`.

The [bounded legacy usability amendment](../governance/1.3.0-bounded-legacy-ux-2026-08-06.md)
adds one final original-WinForms hardening tranche before target qualification.
It supersedes the first source-bound NO-GO Candidate for promotion purposes but
preserves that Candidate immutably as audit evidence. The amendment permits one
reviewed workflow source file and bounded form/control differences; it does not
permit a 2.0 frontend backport or weaken any Beta gate.

## Build and package completion

- install/pin the current serviced VS2017 15.9, VS2022 17.14, and VS2026 stable
  toolchains, then capture their exact installations in an immutable external
  lock bound to clean source commit `C` and its freshly fetched provider ref;
- retain the provider remote URL/ref/fetched SHA receipt, then perform Candidate
  builds offline;
- keep one physical project/source tree;
- add explicit Debug/Release ARM64 configuration without conditional source;
- finalize lane-specific AppConfig/manifest metadata without feature divergence;
- record effective tools version, binary log, actual VBC/reference/ResGen
  paths and hashes, builder OS, source commit, and external-lock SHA-256 for
  every lane;
- add deterministic portable packaging with an exact payload allow-list;
- retain an authenticated entry manifest for each ZIP and prove every extracted
  file name, length, and SHA-256 before trusting `BUILD.txt` or launching;
- add closed x86/x64/ARM64 PE/CorFlags, framework, assembly, product/stage,
  settings, resource, config, and format checks;
- prove two different clean absolute source paths yield identical ZIPs; and
- retain the qualified ZIPs and checksum manifest for possible publication.

The authorized Candidate set includes one classic setup ZIP for each lane. Each
setup bundle consumes the exact matching portable payload bytes, remains
offline, adds no runtime DLL, and must pass clean install, repair, upgrade,
rollback, uninstall, repeated-uninstall, locked-file, downgrade-rejection, and
user-data-preservation cases before setup GO. Portable packages remain
independently usable and authoritative; setup failure does not weaken their
payload contract, but the six-asset overall Beta GO remains false until both
component gates pass.

Candidate mode must fail before compilation for dirty tracked/staged/untracked
source, submodule drift, remote-ref mismatch, wrong source binding, stale
servicing floors, or a changed lock. Candidate builds always use `Rebuild`.
After all three lanes, it must repeat source/ref/submodule/genome/lock closure;
packaging must require that record and one source/lock identity across the exact
three-package set.

## Automated exit gate

- complete frozen-genome comparison with reviewed allow-list entries only;
- prerequisite-planner, guided-flow, stable-key, cancellation, draft-retention,
  layout-reachability, mnemonic, and accessibility regressions;
- unit/characterization coverage for every repair;
- malformed, unsupported, external-entity, oversized, and hostile XML safety;
- failed-load active-state preservation;
- transactional-save fault injection and recovery;
- historical producer and reverse-reader matrix;
- settings migration matrix;
- same source/resources and no runtime DLLs across exactly the three lanes;
- native `0xaa64` ARM64 output with no AnyCPU, emulation, or ARM64EC fallback;
- actual target scripts parse and execute under Windows PowerShell 2;
- target OS build, service pack, native architecture, and installed Full
  Framework are derived mechanically rather than asserted by the operator;
- correct binary identity and deterministic packages; and
- deterministic optional setup bundles and closed payload/installed-state
  manifest verification, when setup is included; and
- clean repository/document/link/generated-output checks.

## Manual exit gate

Run every workflow in the qualification matrix against exact retained packages.
Minimum OS evidence is XP SP3 x86/net40 with .NET Framework 4.0, Windows 7 SP1
x64/net48 with .NET Framework 4.8, and Windows 11 21H2/RTM ARM64/net481 with
separately installed .NET Framework 4.8.1 and native-process proof. Build-host
inspection does not substitute for target-machine execution.
