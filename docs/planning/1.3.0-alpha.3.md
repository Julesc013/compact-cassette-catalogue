Publication: retained engineering preview; intentionally unpublished.

Authority: the [Alpha 3 owner decision](../governance/1.3.0-alpha3-classic-setup-2026-08-05.md).

## Entrance

Alpha 2 is immutable and complete only when its `C -> E -> tag -> P` record,
three portable ZIPs, one external lock, clean-path reproduction, and post-tag
attestation pass. Alpha 3 must descend from Alpha 2 post-tag commit `P`.

Historical Gate 1 remains mandatory before the first main-application behaviour
change. Installer specifications, shared-engine tests, and non-runtime setup
scaffolding may proceed in parallel because they do not change C3 runtime
behaviour.

## Phase 1 — governance and characterization

1. Project the Alpha 3 identity through source, assembly metadata, manifests,
   packages, release notes, and validation controls.
2. Freeze installer/uninstaller project, form, control, resource, and artwork
   baselines before remediation.
3. Adopt the payload and installed-state XML specifications.
4. Classify every static hazard and maintain an S0–S3 defect ledger.
5. Complete historical Gate 1 before application behaviour changes.

## Phase 2 — application S0/S1 repairs

Each outcome receives a reproduction first and one focused implementation
commit:

1. resolve pending tape edits before document transitions;
2. replace recursive close handling with one explicit close gate;
3. preserve state on Save As cancellation and save failure;
4. use one Open-dialog flow and load into temporary state;
5. reject hostile/oversized XML without altering active state;
6. save transactionally with backup and fault injection;
7. detect external edits;
8. replace positional tape construction with named assignments;
9. preserve identifiers and creation dates;
10. protect referenced brand/model/deck deletion;
11. make bulk creation atomic and preserve sequence integrity; and
12. make settings migration retryable and failure-visible.

## Phase 3 — application S2 and defect hunt

Repair every reproducible S2, including model-note source, deck/model counters,
peak/bias/calibration persistence, duplicate deck choices, console path fallback,
nonfatal console writes, and historical display-name references. Add randomized
catalogue invariants, expanded hostile XML, persistence fault injection,
differential historical testing, and lifecycle stress.

## Phase 4 — classic setup engine

1. Add matched x86/net40, x64/net48, and ARM64/net481 configurations to both
   historical projects.
2. Link one shared VB.NET implementation into both EXEs without a DLL.
3. Verify exact adjacent offline payload bytes and environment/elevation.
4. implement safe path policy, staging, journal, clean install, repair, upgrade,
   rollback, registry, and owned shortcuts.
5. Implement manifest discovery, self-relocation, reversible removal, and
   preservation of unknown/user data.
6. Complete directory selection, cancel/failure distinction, progress, errors,
   launch guards, keyboard/DPI/high-contrast behaviour, and image deduplication.
7. Build deterministic setup bundles from the already-qualified portable
   payload bytes.

Implementation status on 5 August 2026: steps 1–7 pass source, 46 shared-engine
regressions, six closed PE/framework/config builds, deterministic Preparation
packaging, exact portable-byte reuse, canonical manifest verification, four
rewritten-sidecar tamper cases, artwork deduplication, and keyboard/screen-reader
source gates. A PowerShell 2-compatible target preflight now binds the exact
ten-entry extraction to retained setup-package evidence and derives the real
lane environment before the wizard can be launched deliberately. Two clean
Candidate paths and the exact target-OS mutation/UI matrix remain exit gates;
no retained Alpha 3 distribution is claimed.

## Exit gate

- all S0/S1 and reproducible S2 defects have focused regression evidence;
- expanded XML, randomized invariant, persistence-fault, and lifecycle suites
  pass;
- both setup projects build source-identically in all three lanes;
- two clean path-distinct product and setup builds reproduce exact bytes;
- clean install, repair, reinstall, upgrade, downgrade rejection, rollback,
  uninstall, repeated uninstall, locked-file, and user-data preservation cases
  pass on each exact target environment;
- retained x86/x64/ARM64 PE/framework and package/payload/installed-manifest
  evidence closes;
- x86, x64, and native ARM64 target-machine workflows pass;
- `v1.3.0a3` is an annotated tag with post-tag attestation;
- packages are retained but no public release/feed/legacy movement occurs.

Only then is the completed Alpha 3 scope technically eligible for Beta 1.
Stop before any Beta-labelled tag, package, or distribution until explicit
human approval is received.
