# C3 1.3.0 durable classic-setup journal

Status: repository preparation complete; exact target-machine interruption qualification remains open.

## Authority and storage

Both old-style VB.NET setup projects link the same `SetupShared` source files directly. No setup DLL, service, updater, network client, MSI, MSIX, or ClickOnce runtime path is introduced.

For an installation root named `Compact Cassette Catalogue`, the active journal is a sibling of the product directory:

```text
.<product-directory>.c3-transaction.xml
```

Settled records are retained byte-for-byte below the sibling audit directory:

```text
.<product-directory>.c3-transactions/
  <transaction-id>-complete.xml
  <transaction-id>-rollback-complete.xml
```

Every record closes the operation, phase, transaction-owned staging and backup paths, root-existence fact, lane, architecture, framework, payload source commit, payload-manifest SHA-256, setup source commit, setup executable SHA-256, intended installed-state SHA-256, UTC timestamps, immutable identity digest, and complete-record digest. XML parsing prohibits DTDs, namespaces, child content, and unexpected attributes. Work paths must be exact transaction-ID-derived siblings of the governed Program Files root.

Journal replacement writes a same-directory temporary file with `FileOptions.WriteThrough`, calls `Flush(true)`, and uses atomic `File.Replace` after the first record. A changed journal, changed installed-state image, changed payload byte, unexpected registry image, or unexpected shortcut fails closed and leaves the active journal for diagnosis.

Staged payload, pending installed-state, recovery-state, and written shortcut files are flushed before their corresponding phase can advance. Windows registry writes and deletions call `RegistryKey.Flush()` before verification and phase advancement.

## Closed phase order

The only forward order is:

```text
prepared
staged
backup-complete
payload-promoted
shortcuts-mutated
registry-mutated
state-committed
complete
```

Any unsettled forward phase may enter:

```text
rollback-started
rollback-complete
```

Illegal jumps and mutations after a settled phase are rejected.

`C3.installed.xml` is first built and hashed in the transaction staging directory. It is not moved into the product directory until all payload files, common shortcuts, and the HKLM uninstall registration have reached and passed their owned after-image checks. Therefore the public `complete="true"` installed state cannot precede durable files, shortcuts, or registration.

Uninstall keeps an authenticated installed-state recovery copy before quarantining owned payload bytes. It removes only the seven manifest-owned files, recorded common shortcuts, exact lane-owned HKLM key, and installed-state file. Catalogues, settings, and all other unknown files remain outside the ownership set.

## Startup and recovery

Installer startup checks the default per-machine root before the wizard proceeds. Installed and relocated uninstaller startup derives the governed root from the exact installed-state argument and recovers before state/relocation validation. The operation entry points repeat the check before any new mutation, covering custom install roots and callers outside the forms.

An incomplete operation always attempts rollback to its authenticated before image. A completed operation only archives its settled journal and removes transaction-owned work directories. A mismatch is never adopted, overwritten, or inferred to be success.

## Repository crash evidence

The .NET Framework 4.0 setup characterization executable launches a new child process with disk-backed registry and shortcut fixtures. The child calls `Environment.Exit(97)` immediately after each durable phase write, bypassing every `Catch` and `Finally` block. A fresh caller then recovers the retained bytes.

The matrix covers all ten phases independently for:

- clean install;
- repair, including catalogue and settings preservation;
- uninstall, including unknown-file preservation.

Additional regressions prove recovery-before-successor setup, altered promoted-byte refusal, journal tamper rejection, illegal phase rejection, retained settled evidence, and installed-state commit-last ordering.

These maintained-host subprocess tests establish process-death logic and source-level .NET 4.0 compatibility. They do not claim power-loss durability of a particular filesystem, Windows registry implementation, WSH shortcut implementation, reboot cleanup path, or exact XP, Windows 7, or native ARM64 machine. Those remain mandatory target qualification rows.
