## Target environments

| Lane | Builder proof | Minimum runtime proof |
| --- | --- | --- |
| `win-x86-net40` | VS2017 15.9 family, net40 references, x86 binary inspection | XP SP3 x86 with .NET Framework 4.0 Full and separately recorded final 4.0.3 state |
| `win-x64-net48` | VS2022 17.14 family, net48 references, x64 binary inspection | Fully serviced Windows 7 SP1 x64 with .NET Framework 4.8, plus later x64 smoke tests |
| `win-arm64-net481` | VS2026 family, net481 references, ARM64 binary inspection | Windows 11 21H2/RTM ARM64 with .NET Framework 4.8.1, native-process and full workflow proof |

Target verification transfers the exact retained ZIP and package-entry
manifest, checks their expected SHA-256 values, verifies every extracted file
name/length/hash, derives the target facts, and retains runtime evidence. The
friendly environment ID is derived output, not operator input. A builder-side
launch is not required when the host cannot natively execute the lane and never
qualifies ARM64 from an x64 process.
Use the [target-runtime record template](1.3.0-target-runtime-record.md) for each
package/environment result.

Setup qualification separately uses the
[target classic-setup record template](1.3.0-target-setup-record.md).
`build/verify-target-setup.ps1` performs a non-mutating authenticated bundle and
environment preflight by default. Its `-LaunchSetup` switch is deliberate and
does not convert process exit into a PASS; each real mutation, rollback,
ownership, accessibility, and uninstall result must be recorded explicitly.

## Required result record

For every executed row, capture source SHA, package name/hash, lane, toolchain,
OS image, user-profile isolation, fixture/catalogue identity, expected result,
actual result, operator, date, and retained evidence location. A blank result is
not a pass.
