## Automated cases

- ancestry, immutable archive reachability, and permanent-ref roles;
- production path/type/control/resource/application identity genome;
- no C#, new production project, new runtime assembly, or conditional lane logic;
- exact settings names/types/scopes/defaults and migration results;
- exact DataSet table/column/type/order/key and catalogue 1.1.0 contract;
- malformed, unsupported, DTD/entity, oversized, and hostile XML rejection;
- failed-load state/path preservation;
- transactional save, replacement, backup, cleanup, and external-edit handling;
- tape field, date, identifier, sequence, bulk atomicity, and counter integrity;
- referential deletion/rename protection;
- historical producer reads and reverse reads by v1.1.2/v1.2.0b1;
- lane source/resource/config parity, PE CPU, framework and assembly metadata;
- x86 `014c`/PE32/32BITREQ, x64 `8664`/PE32+, and native ARM64
  `aa64`/PE32+ closed mapping with ILONLY CorFlags;
- clean remote-bound source plus an immutable external lock covering exact
  Visual Studio/MSBuild/VBC/reference-assembly/ResGen/source/host evidence;
- explicit provider-ref fetch receipt before offline Candidate builds;
- one source/mode/locked-status/lock identity across the complete three-package
  set, plus final source/ref/submodule/genome/lock closure after all lanes;
- exact payload allow-list, authenticated extracted-entry manifests, and
  deterministic ZIP reproduction;
- optional setup bundles consuming the verified portable bytes, closed payload
  and installed-state manifests, transactional install/repair/upgrade/rollback,
  owned-file uninstall, and preservation of unknown and user data;
- exact six-executable setup PE/framework/config/build-evidence closure,
  canonical payload-manifest bytes, five portable-entry byte reuse, and
  rewritten-checksum-sidecar tamper rejection;
- actual PowerShell 2 execution of XP-side tooling and mechanical OS build,
  service pack, architecture, and Full Framework enforcement; and
- clean docs, links, whitespace, generated output, and worktree.

## Manual workflows

- launch and ordinary close;
- New/Open/Save/Save As and Save As cancellation;
- Save/Discard/Cancel at close/open/new and pending-editor transitions;
- add/edit/delete brands, models, decks, and single/bulk tapes;
- list, filter, select, scroll, and edit from every list form;
- invalid/unsupported/hostile XML while a real catalogue is active;
- external modification, read-only/unavailable destination, and backup recovery;
- console display/export and write failure;
- settings persistence, real-profile upgrade, failed upgrade, and retry;
- automatic checks disabled, blocked-network manual check, browser failure;
- cross-lane catalogue exchange, side-by-side 1.2/1.3, and rollback to 1.2.

For each optional setup lane, also execute clean install, cancel before
mutation, repair, same-lane upgrade, downgrade/lane-change rejection, injected
rollback, running-C3 refusal, altered-owned-state refusal, self-relocated
uninstall, repeated uninstall, reboot-locked self-cleanup, unknown/catalogue
preservation, keyboard-only navigation, DPI, and high-contrast workflows.

## Target environments

| Lane | Builder proof | Minimum runtime proof |
| --- | --- | --- |
| `win-x86-net40` | VS2017 15.9 family, net40 references, x86 binary inspection | XP SP3 x86 with .NET Framework 4.0 Full and separately recorded final 4.0.3 state |
| `win-x64-net48` | VS2022 17.14 family, net48 references, x64 binary inspection | Fully serviced Windows 7 SP1 x64 with .NET Framework 4.8, plus later x64 smoke tests |
| `win-arm64-net481` | VS2026 family, net481 references, ARM64 binary inspection | Windows 11 21H2/RTM ARM64 with .NET Framework 4.8.1, native-process and full workflow proof |

Target verification transfers the exact retained ZIP and package-entry
manifest, checks their expected SHA-256 values, verifies every extracted file
name/length/hash, derives the target facts, and retains runtime evidence. The
friendly environment ID is derived output, not operator input. A builder-side
launch is not required when the host cannot natively execute the lane and never
qualifies ARM64 from an x64 process.
Use the [target-runtime record template](1.3.0-target-runtime-record.md) for each
package/environment result.

## Required result record

For every executed row, capture source SHA, package name/hash, lane, toolchain,
OS image, user-profile isolation, fixture/catalogue identity, expected result,
actual result, operator, date, and retained evidence location. A blank result is
not a pass.
