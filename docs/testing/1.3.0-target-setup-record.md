# C3 1.3.0 target setup qualification record

Copy this template for every setup scenario, package, and exact target
environment. Never edit a completed result to describe rebuilt bytes. Builder
inspection and shared-engine tests do not qualify real Windows mutation.

Run `build/verify-target-setup.ps1` first without `-LaunchSetup`. Supply the
transferred setup ZIP, its retained entry manifest, its exact extraction, and
both expected release-evidence SHA-256 values. Do not pass
`-TargetEnvironmentId`; the verifier derives the target identity. Attach its
generated evidence. The preflight must establish:

- [ ] Setup ZIP and retained entry-manifest hashes match release evidence.
- [ ] Extraction contains exactly three ordinary root files, one ordinary
  `payload` directory, and its exact seven ordinary payload files.
- [ ] Every extracted length and hash matches the authenticated entry manifest.
- [ ] Setup, portable, release, lane, source, toolchain mode, and lock identity
  are mutually consistent.
- [ ] Authenticated `payload.xml` matches the release/lane/source contract.
- [ ] OS build, service pack, native architecture, and Full Framework match the
  selected lane mechanically.
- [ ] No reparse point, extra file, nested directory, DLL, downloaded payload,
  MSI, MSIX, ClickOnce artifact, bootstrapper, updater, or service is present.

Only after preflight passes, rerun with `-LaunchSetup` for the authorized case.
That switch launches the exact verified `SETUP.exe` from its extracted bundle;
it does not interpret a zero exit code as qualification. The checklists and
retained installed-state evidence below determine the result.

## Clean install and cancellation

- [ ] Standard-user launch requests elevation on UAC systems; rejecting the
  prompt makes no product change.
- [ ] Cancel on introduction, directory, and ready pages makes no product,
  registry, shortcut, scheduled-task, service, or profile change.
- [ ] Invalid, relative, UNC, device, volume-root, Windows-root, Program
  Files-root, profile-root, reparse-point, and unowned nonempty destinations
  are rejected before mutation.
- [ ] Wrong architecture, framework, lane, release identity, package hash,
  payload hash, missing file, extra file, and running-C3 preflights fail closed.
- [ ] Clean install copies exactly the seven authenticated payload files and
  adds only `C3.installed.xml` as setup-owned state.
- [ ] Installed EXE/config bytes equal the bound portable package bytes.
- [ ] Installed uninstaller/config bytes equal the authenticated setup payload.
- [ ] `C3.installed.xml` strictly records the exact lane, release, source,
  transaction, files, hashes, registry key, shortcuts, and complete state.
- [ ] Add/Remove Programs contains the exact natural-architecture lane key and
  closed owned value set; no false quiet-repair/uninstall claim appears.
- [ ] Required all-users Start Menu and selected all-users Desktop shortcuts
  have exact target, working directory, and description.
- [ ] Normal application launch after install needs no administrator rights.
- [ ] No network access is attempted and blocked networking is nonfatal.

## Repair, reinstall, and upgrade

- [ ] Same-byte reinstall is safe and leaves one coherent installed state.
- [ ] Repair restores missing/altered owned bytes only after authenticating the
  prior installed state and incoming bundle.
- [ ] Repair changes the optional Desktop shortcut transactionally while the
  mandatory Start Menu shortcut remains owned.
- [ ] Same-lane older-to-newer upgrade preserves catalogue/user data and records
  the prior release/source in installed state.
- [ ] Downgrade is rejected before mutation.
- [ ] Cross-lane replacement is rejected before mutation.
- [ ] Unowned file, registry-key, registry-value, or shortcut collision is
  rejected without adopting or overwriting it.
- [ ] Starting repair/upgrade while C3 is running is rejected without mutation.

## Failure injection and rollback

Record the injection method and before/after hashes for every case.

- [ ] Failure while staging leaves the prior installation untouched.
- [ ] Failure after owned-file replacement restores exact prior bytes/state.
- [ ] Failure during registry mutation restores prior files/state/registry.
- [ ] Failure during shortcut mutation restores prior files/state/registry and
  shortcuts.
- [ ] Failure after complete integration but before commit restores the exact
  prior installation.
- [ ] Insufficient rollback space is rejected before mutation.
- [ ] Read-only/locked destination and antivirus-style access denial fail
  visibly and preserve/recover prior ownership.
- [ ] Abrupt process termination/power-loss simulation leaves evidence that can
  be recovered safely or blocks further mutation pending operator action.
- [ ] Install process termination is exercised separately after each durable
  journal phase: prepared, staged, backup-complete, payload-promoted,
  shortcuts-mutated, registry-mutated, state-committed, complete,
  rollback-started, and rollback-complete.
- [ ] Repair repeats the same ten phase boundaries and preserves exact
  catalogue, settings, and other unknown-file hashes.
- [ ] Uninstall repeats the same ten phase boundaries and restores or completes
  only the authenticated files, HKLM registration, and common shortcuts.
- [ ] Altered journal, promoted payload, recovery state, registry, and shortcut
  before/after images fail closed with the active journal retained.

## Uninstall and ownership safety

- [ ] Add/Remove Programs launches the authenticated installed uninstaller.
- [ ] Direct uninstaller launch without the exact authenticated installed-state
  argument refuses mutation.
- [ ] Uninstaller self-relocates to its owned temporary pair and authenticates
  the relocated executable/config before removal.
- [ ] Running C3 blocks uninstall before mutation.
- [ ] Modified/missing owned file, installed-state field, registry value, or
  shortcut blocks unsafe deletion and reports the exact failure.
- [ ] Normal uninstall removes only authenticated owned files/state, exact
  registry values/key, and exact owned shortcuts.
- [ ] Unknown files, catalogue XML, profile settings, exports, logs, and an
  otherwise nonempty install directory are preserved.
- [ ] Injected uninstall failure restores files/state/registry/shortcuts.
- [ ] Repeated uninstall is a safe, visible no-op/refusal and deletes nothing
  outside authenticated ownership.
- [ ] Locked relocated uninstaller cleanup is limited to its verified temporary
  EXE/config pair and succeeds after reboot where required.
- [ ] No orphan service, scheduled task, updater, bootstrapper, temporary
  payload, or setup-owned registry/shortcut entry remains after success.

## Wizard, accessibility, and display

- [ ] Keyboard-only navigation covers all pages, controls, Back/Next/Install,
  Cancel confirmation, Finish, and uninstaller actions with visible focus.
- [ ] Mnemonics and dynamic default buttons invoke only the displayed action.
- [ ] Screen reader announces wizard, directory, progress, status, completion,
  failure, and uninstaller semantics meaningfully.
- [ ] 100%, 125%, 150%, 200%, and target-native DPI do not clip, overlap, hide,
  or make controls unreachable.
- [ ] High Contrast and system font/color changes preserve readable text,
  visible focus, buttons, progress, errors, and selection state.
- [ ] Original classic wizard artwork is recognizable and appears once per
  visible form without duplicated embedded resources.
- [ ] Cancellation, validation failure, rollback failure, success, and reboot
  cleanup are distinct and actionable; no false success is shown.
