# C3 1.3.0 Alpha 3 implementation and Beta 1 defect ledger

Status: source implementation complete; exact historical and target-machine
qualification remains open. A row's implementation closes only with a
reproduction, focused fix, and regression. Its release disposition closes only
after the required real-machine evidence is retained.

## Severity

| Severity | Definition | Alpha 3 rule |
| --- | --- | --- |
| S0 | data loss/corruption, arbitrary mutation, security failure | must fix |
| S1 | broken lifecycle/integrity, unrecoverable workflow, silent loss | must fix |
| S2 | wrong value/counter/field/setting or common UX behaviour | fix every reproducible case |
| S3 | cosmetic or low-impact inconvenience | may defer with evidence |

## Static hazard sweep

Every production `.vb` hit for broad/silent catches, `Application.Exit`, row
indexing/finds, positional `Object()` construction, external-value conversions,
path concatenation, delete/process/registry calls, XML read/write, default-form
access, dirty-state mutation, and data-writing control events is classified in
this ledger before Beta qualification. A search hit is evidence to review, not
an automatic code change.

## Test programmes

- differential catalogue actions through v1.1.2, v1.2.0b1 x86/x64, and current
  x86/x64/ARM64 where executable;
- randomized catalogue/action invariants after every mutation;
- XML truncation, schema/type/namespace/entity/depth/size/culture/read-race and
  partial-parse failures while preserving active state;
- save fault injection at create/write/flush/reopen/backup/replace/metadata/
  cleanup; and
- repeated lifecycle stress across X, File Exit, shutdown/logoff, pending edit,
  dirty state, Save/Discard/Cancel, Save As cancel/failure, and rapid repeats.

`tests/C3.Settings.Characterization` mechanically pins the APP-010 settings
schema/startup/normalization contract against the read-only legacy fixtures and
the APP-015 diagnostic-source contract. These regressions do not replace the
required isolated Windows-profile transitions or target UI/failure workflows.

The repository-side regression baseline is 21 lifecycle/persistence tests,
8 integrity tests, 6 settings/diagnostics tests, and 85 setup tests. These 120
automated checks establish source implementation evidence; they do not replace
the historical Gate 1 executions or exact XP, Windows 7, and native ARM64
qualification records.
