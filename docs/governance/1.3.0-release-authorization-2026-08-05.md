# C3 1.3.0 preview release authorization

Decision date: 5 August 2026

Status: ratified owner decision

This decision controls who may create preview identities and distributions on
`dev/1.x`. It does not reduce any technical, compatibility, evidence, or
publication gate in the milestone plans.

## Alpha authority

Codex is authorized to create annotated C3 1.3.0 Alpha tags and to build and
retain Alpha distributions when the applicable documented Alpha checks pass.
An Alpha remains an engineering preview: it does not advance `legacy/1.x`, the
stable update feed, or any stable support claim.

This standing authority does not choose an Alpha version number by implication.
Every new Alpha tag must name a deliberate source identity, must be annotated,
and must preserve the immutable existing `v1.3.0a1` object and target. Producing
an Alpha distribution does not by itself authorize publishing it publicly.

## Beta authority

Explicit human approval is required before any C3 1.3.0 Beta version is created.
The approval boundary applies independently to:

- creating or moving a Beta tag;
- producing or retaining a Beta-labelled distribution; and
- publishing Beta assets or a prerelease.

Passing the Beta technical gates makes a source and its exact retained bytes
eligible for approval; it does not supply that approval. Codex may prepare the
source, tests, evidence, external lock, and non-Beta control-path artifacts, but
must stop before creating `v1.3.0b1` or any other Beta-labelled bytes until the
owner explicitly approves that action.

## Stable and publication boundary

Stable continues to require the owner-accepted Beta source and retained
packages, the complete stable qualification plan, and the existing explicit
publication/feed/branch controls. This Alpha authorization does not authorize
public release creation, `legacy/1.x` movement, or update-feed promotion.
