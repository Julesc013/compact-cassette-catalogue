# C3 1.3.0 bounded legacy usability amendment

Date: 6 August 2026

Status: ratified owner decision

> **Subsequent correction:** Alpha 4 owner testing proved that the bounded
> runtime anchor/scroll policy was not a sufficient layout mechanism. The
> [Alpha 5 layout decision](1.3.0-alpha5-layout-stabilization-2026-08-06.md)
> preserves this document's workflow contracts but supersedes its
> presentation-geometry implementation.

## Decision

C3 1.3.0 receives one bounded legacy usability and layout-remediation tranche
before final Beta 1 qualification. This work improves the original WinForms
creation journey, reachability, keyboard use, and large-font behaviour. It is
not a new shell, visual redesign, project split, data-model rewrite, or backport
of the 2.0 frontend architecture.

The first truthful Beta 1 NO-GO Candidate remains immutable at source
`bbebac288f4996939124f882d0e9febcf2e5bdae`. Any output after this decision is
a new source-bound `1.3.0b1` Candidate and must be retained beside, never over,
that record. The Beta label does not change because `v1.3.0b1` has never been
created.

## Included legacy UX contract

- `Add Tape` plans and executes missing Brand -> Model -> Tape prerequisites.
- `Add Model` plans and executes a missing Brand prerequisite.
- recording-side selection can create a missing Deck without discarding the
  in-progress tape draft;
- creation dialogs are fresh owned modal instances with explicit OK/Cancel and
  created-key/display-name results;
- brand, model, and deck selections carry stable keys rather than relying on
  display-text searches;
- Add Brand, Add Model, Add Deck, and Add Tape actions are available beside the
  relevant choices and from their list windows;
- routine omissions and duplicates use field validation while preserving
  entered values;
- guided intermediate success dialogs are suppressed and the journey emits at
  most one final summary;
- an empty catalogue explains the dependency journey and offers Add First
  Tape;
- the main form, tape form, and large list forms remain usable while retaining
  classic controls and layout; Alpha 5 owns the corrected container/geometry
  mechanism and its stronger proof;
- compact dialogs receive owned centring, accept/cancel actions, access keys,
  useful accessible names, and reviewed tab order.

## Architecture boundary

One production file, `CatalogueWorkflow.vb`, is the only approved application
source-topology addition. It contains the pure prerequisite planner, stable
choice/result types, small validation helpers, and the coordination seam around
the existing DataSet, DataTables, and forms.

The original project, assembly, namespace, startup object, DataSet schema,
catalogue `1.1.0` format, forms, resources, and single-EXE/runtime-DLL contract
remain authoritative. No new project, repository layer, domain graph, runtime
DLL, framework dependency, per-user installer, or conditional lane behaviour
is permitted.

## Deferred to 2.0

New navigation or workspace architecture, tabs/sidebars, command palette,
theming, custom rendering, new catalogue fields or format, MVP/MVVM, frontend
abstractions, persisted workspaces, tutorial frameworks, and universal dynamic
PerMonitorV2 DPI behaviour remain 2.0 work. The 1.3 lane continues using
`AutoScaleMode.Font` and proves layout safety at classic DPI/font settings.

## Release consequences

All three portable ZIPs and all three setup ZIPs must be rebuilt because each
setup package authenticates the exact portable payload. The new Candidate must
pass the complete repository suite, reviewed genome differences, three-lane
binary and package verification, and two clean path-distinct builds.

Historical Gate 1 and exact XP, Windows 7, and native ARM64 application/setup
qualification remain mandatory for GO. Until those external records pass,
`v1.3.0b1`, `legacy/1.x`, public publication, the stable feed, `master`, and
`dev/2.x` remain unchanged.
