# C3 1.3.0 Alpha 5 legacy layout stabilization decision

Date: 6 August 2026

Status: ratified owner decision

## Decision

C3 1.3.0 receives one bounded **Legacy Layout Stabilization** tranche before
Beta 1 can be considered. Alpha 5 is a measured migration from absolute form
geometry to role-appropriate WinForms layout ownership. It is not a manual
spacing pass, visual redesign, new shell, source recovery, project split, or
backport of the 2.0 presentation architecture.

The controlling doctrine is:

> Preserve the original information architecture, controls, terminology,
> data-entry density, iconography, and visual character; replace only the
> absolute geometry, resize behaviour, static command placement, and
> inconsistent presentation policy.

The existing guided Brand -> Model -> Tape journey, Deck detours, stable-key
choices, explicit dialog results, draft preservation, validation, application
repairs, and durable classic setup remain authoritative.

## Alpha 4 remains immutable

`v1.3.0a4` and its six retained ZIPs are not moved, rebuilt, renamed, or
replaced. Alpha 4 is the immutable owner-test checkpoint that exposed:

- sibling overlap after resizing;
- controls moving independently of their semantic neighbours;
- form-level scrolling combined with right/bottom anchoring;
- static buttons manufactured from literal rectangles during `Load`;
- geometry mutation after automatic scaling; and
- a property-only layout regression that passed without measuring controls.

The Alpha 4 source/build/package qualification remains truthful. Its layout
claim is superseded by the stronger Alpha 5 geometry and visual gate.

## Meaning of visual fidelity

One absolute pixel map cannot be correct across XP-era Tahoma, Segoe UI,
96/120/144/192 DPI, large fonts, High Contrast, Windows Classic, and modern
themes. C3 therefore uses three explicit fidelity levels:

| Context | Required fidelity |
| --- | --- |
| Windows 7, 96 DPI, approved default size | Pixel-level comparison to an owner-approved reference |
| Other DPI/font profiles | Metric fidelity: hierarchy, baselines, target sizes, relationships, and reachability |
| Other themes and operating systems | Semantic fidelity: native controls, system colours, readable text, visible focus, and no clipping |

At the canonical view, existing controls should remain within zero to two
relative pixels unless a reviewed layout-container change records why that
relationship changed. Higher-scale approval concerns usable visual hierarchy,
not mechanically multiplied coordinates.

## Preserved, changeable, and deferred surfaces

The immutable [1.x visual inheritance contract](../ui/1x-visual-contract.md)
preserves the cassette identity, native window chrome, original editor and
browser information architecture, major semantic groups, terminology, field
order, classic density, common controls, and system theming.

Alpha 5 may change control parentage, layout containers, margins, alignment,
minimum/default size, growth ownership, dedicated scrolling, static command
placement, tab order, access keys, empty-state presentation, and demonstrably
incorrect visible captions.

Alpha 5 may not change the catalogue `1.1.0` format, DataSet, runtime
dependencies, project/assembly topology, application workflows, custom theme,
window chrome, navigation architecture, persisted window/column settings, or
PerMonitorV2 policy. A status strip and column chooser are separately reviewed
enhancements, not hidden requirements of this tranche.

## Implementation discipline

Every mandatory form or form family uses two review stages:

1. **Structural reparenting** adds simple root containers, moves existing
   controls without redesigning fields, declares static commands in the
   Designer, removes matching runtime construction, and compares the default
   view with Alpha 4.
2. **Adaptive behaviour** assigns growth, minimum widths, and dedicated scroll
   fallback, then passes the complete size/scale/content matrix before spacing
   is fine-tuned.

Use `TableLayoutPanel` only for clear row/column relationships,
`FlowLayoutPanel` for command bars, docking for simple fill surfaces, and
`SplitContainer` for filter/result browsers. Deep table nesting is prohibited.
Form-level `AutoScroll` is prohibited on reconstructed forms. A scrollable
viewport owns an autosized top-docked canvas whose direct child is not
right/bottom anchored.

Production `Load`, `Shown`, and `Resize` handlers may populate data and apply
behavioural state. They may not construct known static commands or assign
fixed `ClientSize`, `Bounds`, `Left`, `Top`, `Width`, or `Height` geometry.

## Form scope

Mandatory reconstruction covers:

- `frmMain`;
- `frmTapeNew`;
- `frmTapes`, `frmModels`, `frmBrands`, and `frmDecks`;
- Brand and Model new/edit dialogs;
- `frmDeckNew` and `frmDeckEdit`; and
- any corresponding form with the same runtime-geometry defect.

Console, Find Results, Statistics, Settings, About, installer pages, and
uninstaller pages change only when the Alpha 5 matrix reproduces a concrete
defect. Conditional scope prevents the checkpoint from becoming an
uncontrolled visual rewrite.

## Qualification authority

The [Alpha 5 layout qualification specification](../testing/1.3.0-alpha5-layout-qualification.md)
replaces property-only layout proof. Each size/scale/content cell runs in a new
STA process after handle creation and message processing. Geometry JSON and
text/reachability checks are automated authorities; native real-DPI
screenshots, keyboard runs, High Contrast review, and assistive-technology
walkthroughs are manual authorities. `DrawToBitmap` is diagnostic only.

The intermittent x64 process-without-window observation is tracked separately
as `UI-START-001`. It is not explained or closed by layout work. Alpha 5 must
instrument first-window milestones and prove that construction/layout does not
regress startup latency or introduce a layout loop.

## Genome and source boundary

`CatalogueWorkflow.vb` retains planning, stable choices, creation results,
validation, journey coordination, and testable presentation state. Its
geometry-oriented `CatalogueUx` helpers are removed or reduced to
non-geometric policy.

New layout containers and Designer-declared buttons require one narrow,
reviewed `controlNames` genome exception tied to the geometry suite. The
baseline genome must not be regenerated to hide the migration. No new
production file, assembly, project, runtime DLL, catalogue field, or
lane-specific application source is authorized by this decision.

## Release boundary

The repository remains identified as Alpha 4 during planning and
implementation. It transitions to `1.3.0a5 / Alpha 5 / v1.3.0a5` only after
the functional source, visual/layout, accessibility, startup, build, package,
and reproducibility gates pass.

The retained Alpha 5 asset set, when qualified, is exactly three portable and
three classic-setup ZIPs plus `SHA256SUMS.txt`. Alpha tagging and local
retention follow the standing Alpha authority. Alpha 5 does not authorize a
public GitHub release, Beta-labelled bytes or tag, `master`, `legacy/1.x`,
`dev/2.x`, public-feed, or stable movement. Historical Gate 1 and exact target
qualification run against the final Alpha 5 bytes and remain mandatory for
Beta GO.
