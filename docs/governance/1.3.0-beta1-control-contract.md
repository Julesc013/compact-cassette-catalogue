# C3 1.3.0 Beta 1 control contract

This contract implements the 6 August 2026 owner authorization without
changing the active Alpha 3 implementation identity. The final identity
projection is accepted only as `1.3.0 / Beta 1 / 1.3.0b1 / v1.3.0b1 / beta /
retained-unpublished` with exactly three portable and three classic-setup
Candidate ZIPs.

## Candidate boundary

`assemble-beta1-assets.ps1` refuses a dirty source, a non-Beta manifest, an
unlocked or differently bound external lock, and an existing destination. It
retains the six ZIPs beneath
`artifacts/candidates/1.3.0b1/<full-source-sha>/`, together with checksums,
entry manifests, the immutable lock, its fetched-provider receipt, and a
closed Candidate index. `verify-beta1-assets.ps1` rechecks that closure
without trusting filenames as architecture or source proof.

`verify-beta1.ps1` is the source/Candidate gate. Its optional identity-
transition check requires the explicit full `-IdentityCommit`, proves that
commit is a single-parent ancestor of the later frozen `C-beta`, verifies the
parent's exact Alpha 3 manifest and the commit's exact Beta 1 manifest, and
permits only the closed metadata file set. Full mode additionally requires the
locked build, exact retained Candidate, and two clean path-distinct product
and setup builds.

## Mechanical verdict

`new-beta1-verdict.ps1` consumes the closed gate assessment and derives, rather
than accepts, these component results:

```text
portableBetaGo
classicSetupBetaGo
overallBetaGo
```

Every PASS row must bind one ordinary retained evidence file and SHA-256. A
missing or failed row forces the applicable component to NO-GO. Only complete
overall GO authorizes the tag and legacy-ledger promotion. Neither result can
authorize a public release, feed change, or a change to `master` or `dev/2.x`.

## Qualified topology

The only GO topology is:

```text
C-beta  exact package source
  |
E-beta  direct child; changes only machine and human verdict records
  |     annotated v1.3.0b1 points here
P-beta  direct child; changes only the post-tag attestation
```

The annotated message must state the complete historical, application,
setup-durability, three-target, portable/setup/overall GO and non-publication
boundaries. The post-tag verifier checks the remote tag object and target,
`dev/1.x = P-beta`, unchanged `master` and `dev/2.x` snapshots, the unchanged
1.2.0 public feed, and absence of a public GitHub release. The promotion
wrapper then moves `legacy/1.x` only from its exact old SHA with force-with-
lease, and verifies `legacy/1.x = P-beta`.

No control in this tranche creates a tag, package, release, or branch move.
