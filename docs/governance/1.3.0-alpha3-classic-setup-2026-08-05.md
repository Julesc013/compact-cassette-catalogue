# C3 1.3.0 Alpha 3 classic setup owner decision

Date: 5 August 2026

Status: ratified; supersedes every earlier statement that installers and
uninstallers are categorically outside C3 1.3.0.

## Decision

C3 1.3.0 Alpha 3 is the legacy reliability and classic setup revival
checkpoint. It is the first 1.3 checkpoint authorized to change application
runtime behaviour and to finish the surviving VB.NET installer/uninstaller
intent.

The three portable ZIPs remain the canonical product payloads. The repaired
classic setup is an optional, secondary distribution which consumes those
exact already-qualified bytes. Portable use remains independently supported
and requires no C3 installation or elevation.

The authoritative byte flow is closed:

```text
verified lane build
    -> canonical five-file portable payload
        -> portable ZIP
        -> matching offline classic setup bundle
```

Setup must not rebuild C3, select a latest version, read the public stable feed,
download replacement payloads, mutate the EXE/config, invent an independent
file list, or cross architecture/framework lanes.

## Release authority

- Deliberate annotated Alpha setup tags and retained Alpha-labelled setup ZIPs
  are authorized only after the applicable Alpha gates pass.
- Public Alpha publication is not implied.
- Every Beta-labelled tag or retained portable/setup byte requires explicit
  human approval. A passing Beta technical gate establishes eligibility only.
- Public Beta publication requires separate explicit human approval.
- Stable publication, feed promotion, and `legacy/1.x` advancement remain
  separately gated.

## Product and setup lanes

| Lane | Application and setup target | Minimum target |
| --- | --- | --- |
| `win-x86-net40` | x86 / .NET Framework 4.0 / VS2017 | Windows XP SP3 x86 |
| `win-x64-net48` | x64 / .NET Framework 4.8 / VS2022 | Windows 7 SP1 x64 |
| `win-arm64-net481` | native ARM64 / .NET Framework 4.8.1 / VS2026 | Windows 11 21H2 ARM64 |

Installer and uninstaller retain their original project GUIDs, assembly names,
startup objects, forms, resources, and recognizable wizard. Their AnyCPU/net46
configurations cease to be release authority. One source-identical shared
implementation is linked into both projects; no runtime setup DLL is added.

## Distribution and elevation

Alpha 3 setup is offline, version-bound, and shipped as a deterministic setup
bundle ZIP. The user extracts it normally and runs adjacent `SETUP.exe`.
Per-machine setup deliberately requires elevation at startup, installs below
the operating-system Program Files location, registers in HKLM, and uses common
Start Menu/optional desktop shortcuts. Portable ZIPs remain the no-admin path.

No MSI, MSIX, ClickOnce publication, network bootstrapper, background updater,
service, or self-contained runtime is authorized.

## Safety doctrine

Setup verifies a closed XML payload manifest, file sizes/hashes, PE architecture,
framework/config identity, and setup/uninstaller identity before mutation. It
stages on the destination volume, commits transactionally, verifies installed
state, and rolls back on failure.

Uninstall acts only on a validated installed-state ownership manifest. It
preserves catalogue XML, user settings, logs/exports outside the install root,
unknown files, and any non-empty directory containing unowned content. It uses
a relocated temporary worker so it can remove its installed copy honestly.

## Universal Setup

Universal Setup remains the future replacement and may consume the same
qualified payload/installed-state contracts. It does not block Alpha 3 and may
not rebuild, delay, or redefine the legacy core release.
