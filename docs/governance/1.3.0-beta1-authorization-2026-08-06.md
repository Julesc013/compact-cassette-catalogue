# C3 1.3.0 Beta 1 Candidate authorization

Decision date: 6 August 2026

Status: ratified owner decision; supersedes the Beta-approval prohibition in
the 5 August preview authorization for the exact operations below.

## Authorized operations

Codex is authorized to:

1. complete the approved C3 1.3.0 legacy functional and setup-hardening scope;
2. project the final frozen source to the exact `1.3.0b1 / Beta 1 /
   v1.3.0b1` retained-unpublished identity;
3. build and retain the three Beta-labelled portable Candidate ZIPs and three
   Beta-labelled classic-setup Candidate ZIPs;
4. create annotated tag `v1.3.0b1` only after every technical, historical,
   reproducibility, application-runtime, and exact target-setup gate passes;
5. create the evidence-only and post-tag commits for that complete GO; and
6. fast-forward `legacy/1.x` to the qualified post-tag checkpoint only on that
   complete GO, using exact-old-SHA lease protection.

Producing a Candidate byte is not a qualification claim. A missing or failed
gate produces a retained, source-bound NO-GO Candidate and prohibits the tag
and legacy-ledger movement.

## Operations not authorized

This decision does not authorize:

- a public GitHub release or upload of public prerelease assets;
- any change to `master` or `dev/2.x`;
- any change to the root `VERSION` feed, which remains `1.2.0 / Release /
  14/05/2026` throughout Beta;
- `v1.3.0`, stable publication, or stable-feed promotion;
- raw EXEs as authoritative downloads;
- a per-user installer or any new delivery mode; or
- invented, inferred, emulated, or synthetically completed target evidence.

## Permanent branch contract

```text
dev/1.x       moving legacy development
legacy/1.x    qualified legacy checkpoint ledger
dev/2.x       moving 2.x development
master        qualified 2.x checkpoint ledger
```

C3 1.x is never merged into `master`. A later approved GitHub prerelease may
be created directly from `v1.3.0b1` on the legacy lineage.

## Milestone amendment

Alpha 3 remains the internal implementation phase. Because `v1.3.0a3` was
never created, its separate retained-distribution/tag pass is superseded by
the authorized Beta 1 qualification. After the complete Alpha 3 functional
scope passes, one audited metadata-only transition creates Beta identity and
the expensive locked build, clean-path reproduction, historical closure, and
target qualification run once against the exact Beta bytes.

This amendment waives no historical, application, setup-durability,
reproducibility, runtime, accessibility, or target-machine gate.

## Terminal outcomes

GO requires complete source, build, historical, and exact-target evidence. It
uses `C-beta -> E-beta -> annotated tag -> P-beta`; `dev/1.x` and
`legacy/1.x` then equal `P-beta`, while `master`, `dev/2.x`, `VERSION`, and
public releases remain unchanged.

NO-GO retains maximum truthful focused repairs and any buildable Beta
Candidate bytes under a full-source-SHA path. It records separate
`portableBetaGo`, `classicSetupBetaGo`, and `overallBetaGo` verdicts, creates
no Beta tag, and moves no qualified ledger.
