## Implemented contract

- `CatalogueWorkflow.vb` is the only new application source file. It contains
  the pure prerequisite planner, stable choice/result/validation records, the
  existing-dialog coordinator, and bounded classic layout helpers.
- Add Tape executes Brand -> Model -> Tape when required. Add Model executes
  Brand -> Model when required. Confirmed prerequisites remain in the
  catalogue if a later step is cancelled.
- Add Model and Add Tape expose owned inline prerequisite actions. All four
  entity list windows expose owned Add actions and owned modal edit dialogs.
- Brand, Model, Deck, and Tape creation dialogs expose `CreatedKey`,
  `CreatedDisplayName`, and `SuppressSuccessMessage`; callers own refresh and
  continuation.
- Brand/model/deck combo entries carry exact keys. Preferred brand, model, and
  deck properties select only the explicitly supplied identity.
- Routine omissions and duplicates use `ValidationIssue` plus `ErrorProvider`,
  preserve entered values, and focus the first invalid control.
- Intermediate guided success dialogs are suppressed; the completed journey
  produces at most one summary when the existing message preference is on.
- Recording Side A or B with no Deck opens Add Deck and resumes in the same
  live form. Cancellation unchecks the side. A successful inline deck refresh
  selects the new deck without replacing the opposite side's prior key.
- The main empty state offers Add First Tape. Main, Tape, and all entity list
  windows are sizable, maximizable, font-scaled, and scroll-safe. Creation and
  inline actions have access keys, accept/cancel defaults, accessible names,
  descriptions, and deterministic tab positions.
