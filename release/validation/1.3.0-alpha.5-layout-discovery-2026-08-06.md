# C3 1.3.0 Alpha 5 layout discovery — 6 August 2026

Result: **PASS for test-first reproduction of the Alpha 4 layout mechanism.**

This is failing-layout characterization, not Alpha 5 layout qualification.
The measured application source is clean synchronized `dev/1.x` commit
`a0982e0d09951ab0f0656479379375068e938051`; that commit differs from the
Alpha 4 source only by documentation and byte-identical setup-source topology
work relevant to this test.

## Harness

`C3.Layout.Characterization` is a .NET Framework 4.0 x86 STA executable that
accepts one form/size/scale/content cell, creates and shows the real production
form, creates native handles, applies the requested bounds and font-relative
profile, performs layout, and retains:

- the visible control tree and parent paths;
- form-relative bounds and preferred/measured text sizes;
- docking, anchoring, AutoSize, tab, accessibility, scroll-ancestry, and handle
  state;
- closed failure codes; and
- an optional `DrawToBitmap` diagnostic PNG.

`build/test-layout.ps1` starts a new executable process for every cell, hashes
every JSON/PNG and the runner, and writes a closed summary. Discovery and
qualification are distinct modes: discovery requires the known Alpha 4 root
cause, while qualification will require zero failures over the expanded
matrix.

`build/validate-layout-source-policy.ps1` independently scans non-Designer
production VB files for the runtime helper calls, fixed bounds, static control
construction, and literal rectangles prohibited by the Alpha 5 contract.

## Reproduced baseline

Six independent 800×552, 1.00-scale, ordinary-content processes reproduced:

| Form | Closed observations |
| --- | --- |
| `frmMain` | form AutoScroll; empty/data, Identification/Scroll, and Identification/Actions intersections; five right/bottom-anchored form children; explicit known-collision proof |
| `frmTapeNew` | form AutoScroll; duplicate root tab index; Add/Add Deck/Cancel anchored against the scrolling form |
| `frmTapes` | form AutoScroll; duplicate command tab index; fixed Actions/Results/Filters anchored against the scrolling form |
| `frmModels` | same invalid browser mechanism |
| `frmBrands` | same invalid browser mechanism |
| `frmDecks` | same invalid browser mechanism |

The source-policy discovery found 52 exact violations across the 10 expected
files: `CatalogueWorkflow.vb`, the Main/TapeNew forms, four browsers, and the
BrandNew/ModelNew/DeckNew dialog sources. This closes the reproduction gate;
it deliberately does not close any reconstruction or adaptive-layout gate.

## Boundary

No production application source, Designer, resource, release identity,
package, tag, feed, `master`, `legacy/1.x`, or `dev/2.x` surface changed in this
test-first tranche. The next implementation step is to declare known static
commands in their Designers and delete their equivalent runtime construction.
