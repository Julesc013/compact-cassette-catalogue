## Alpha 4 implementation outcome

ADR 0005 is accepted. C3 now has one strict native-v2 reader, deterministic
writer, stable typed graph, and transactional store behind the language-neutral
`spec/catalogue/v2.0.0` contract. The format is plain UTF-8 XML without a BOM,
uses canonical LF and deterministic ordering, validates every typed reference,
and rejects unsafe, oversized, structurally unknown, or noncanonical input.

Legacy v1.1 remains a named compatibility profile. Migration first performs a
read-only deterministic dry run; convert-copy writes a new verified native file,
machine/human reports, and a recovery journal without replacing its source.
Repeated mapping is stable. Interrupted work resumes only from verified source
and destination revisions. Native-to-v1.1 export previews and records every
native-only or flattened value and remains readable by the accepted historical
baseline.

The canonical `src/C3.Cli/C3.Cli.csproj` builds net40/AnyCPU `c3.exe`. Its eight
process scenarios validate legacy/native files, dry-run and execute migration,
recover, export legacy, reject existing outputs, and project stable exit codes.
It is a thin shell over the same Infrastructure services and does not duplicate
format, mapping, transaction, or loss policy.

Distribution is machine-owned by two strict TOML lane profiles and the single
`release/profiles/portable-payload.v1.json` file list. Both archives contain one
versioned root with exactly nine payload entries: Desktop/configuration, three
C3 libraries, identical `c3.exe`, build identity, README, and release notes.
Neither ZIP packaging nor a future setup binding owns a second enumeration.

## Native/legacy compatibility evidence

The production native writer matched the schema and canonical fixtures, rewrote
canonical documents byte-identically, and remained culture independent. The
reader/store rejected external entities, unknown structure, duplicate or invalid
values, unresolved typed references, unsafe nesting, revision mismatches, and
external edits. Transaction tests preserved destination and backup bytes and
removed only owned temporary output.

`build/test-compatibility-baselines.ps1` hash-verified the exact historical
binaries and passed 12 current-output/historical-reader rows in both current
lanes. For each supported producer family, both the current v1.1 writer output
and native loss-aware v1.1 export were opened/written by the baseline binary and
reopened by the current reader. The artifacts covered stable 1.0.0, 1.1.0,
1.1.1, and 1.1.2 plus maintained public 1.2.0 Beta 1 x86 and x64 producers.

No conversion silently overwrote a legacy original. Missing, ambiguous, unsafe,
or conflicting migration state produced a typed refusal rather than guessed
data. No known catalogue-corruption or data-loss path remained.
