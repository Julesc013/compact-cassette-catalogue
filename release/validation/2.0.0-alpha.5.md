## Active implementation evidence

The shared C# Brands form, presenter, interaction patterns, and reversible
commands are implemented on `dev/2.x`. Focused automated gates cover presenter
behavior, UI construction on an STA thread, accessibility names, DPI mode,
resizable/minimum layout, both host project references, retirement of duplicate
VB Brand forms, and both lane builds. Browse and create-state off-screen renders
were inspected on the maintained development host. Both freshly staged portable
executables also passed the exact main-window to `F6` to shared-Brands-window
launch path and then closed gracefully with exit code 0.

The development performance command populated all 676 possible two-letter Brand
codes and ran 20 warm iterations. It reported maximum presenter times of 0.459
ms unfiltered refresh, 0.981 ms filtered refresh, and 0.883 ms editor activation
on the maintained host. The normal characterization gate enforces conservative
regression ceilings. Frozen-candidate measurements will replace these provisional
values and add packaged paint/input/memory observations.

Visual Studio 2017 Enterprise 15.9 (`devenv.exe` product version
`15.9.37327.18`) opened `BrandWorkspaceForm.cs` using the WinForms designer from
an isolated detached worktree at
`b60a43b0a94e4175b0fbd07211a19f4e7c3f71f3`. The form and solution were saved,
the IDE exited normally, and both `git status --short` and `git diff --check`
remained empty afterward. This proves that the checked-in designer/code-behind
pair round-trips through the canonical current designer without generated churn.
It does not substitute for runtime interaction or visual matrices.
