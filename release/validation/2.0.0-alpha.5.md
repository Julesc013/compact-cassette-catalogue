## Milestone outcome

Alpha 5 establishes one shared C# 7.3/net40 presentation assembly used by both
existing VB executable hosts. The presentation project owns reusable workspace,
list, inspector, editor, validation, feedback, progress, focus, and interaction
patterns; it owns no XML, `DataSet`, persistence, migration, update transport,
preference storage, or catalogue invariant.

The production Brands slice now uses explicit application composition,
document/workspace state, semantic command history, bounded undo/redo, stable
identity selection, drafts, dirty state, reference-protected deletion, and
non-modal status. The obsolete duplicate VB Brand forms and global state seam
are absent. Both runtime lanes execute the same physical feature source.

The final candidate corrects a defect found by exact-package automation: a
filter that temporarily hid a selected Brand had discarded its semantic
selection. The presenter now retains an identity anchor while hidden rows remain
ineligible for edit/delete commands, then restores the exact selection when the
filter clears. Characterization and packaged process evidence cover the fix.

The Desktop also accepts one catalogue path at startup through the same
transactional loader as File > Open. This supplies standard Windows Open-With
behavior and permits deterministic cross-lane reopen proof without relying on a
build host being allowed to steal foreground focus.

ADR 0017 and the goal-first workflow contract are accepted for Alpha 6-12. They
do not claim that the future Tape prerequisite workflow is implemented by this
checkpoint.

## Exact-package workflow and performance

Both retained archives were independently extracted and driven through their
real controls. Each lane created, edited, filtered, cleared the filter, confirmed
deletion, undid/redid, restored, and saved a Brand. Each resulting catalogue was
then launched and reopened by both exact Desktop executables. Both mutation rows
and all four same-lane/cross-lane reopen rows passed.

The run used the maintained Windows 10 build 19045 host with conservative safety
ceilings of 30 seconds startup, 15 seconds Brands open, 5 seconds for a measured
semantic command or paint, and 512 MiB peak working set.

| Lane | Startup | Brands open | Slowest command | Paint | Peak working set |
| --- | ---: | ---: | ---: | ---: | ---: |
| x86/net40 | 2,659.321 ms | 940.123 ms | 1,045.340 ms | 16.433 ms | 90,898,432 bytes |
| x64/net48 | 2,777.971 ms | 1,042.289 ms | 1,084.631 ms | 15.394 ms | 127,488,000 bytes |

These are candidate baselines on the named host, not universal hardware or
minimum-OS claims. No known catalogue corruption, partial mutation, selection-
driven wrong-record action, or data-loss path remained in the accepted Alpha 5
surface.
