## Verdict

`UI-START-001` is resolved for the executable builder lanes. The application
reached a visible main window, completed its first idle cycle, accepted a
normal close request, and exited with code zero in all 40 retained launches.
No run required cleanup termination.

The Alpha 4 process-without-window observation was reproduced when the smoke
harness forced the process to start minimized. Opt-in milestones stopped at
`main.set-visible.enter` after `main.handle-created`, before `Load`. The same
binary followed the complete startup path when launched with the ordinary
normal window state. The smoke and lifecycle tools now mechanically prohibit
the forced-minimized first-show path.

This closes a verification-harness defect. It is not presented as evidence
that layout code repaired application startup.
