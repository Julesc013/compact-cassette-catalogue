## Candidate source and lock authority

- The repository `build/toolchain-lock.json` is schema-2 template data only.
  Candidate mode rejects it because a tracked lock cannot bind the commit that
  contains its own resulting SHA.
- Candidate mode requires an absolute external lock with `status=locked`,
  `sourceCommit=C`, an expected `refs/remotes/...` ref resolving exactly to
  `C`, exact lane/tool hashes, and a retained lock SHA-256.
- Before compilation it rejects staged, modified, or untracked files;
  uninitialized/mismatched/conflicted submodules; genome/projection drift;
  wrong source binding; stale servicing floors; and a non-rebuild invocation.
- The lock is hashed before the build and again after all lanes. A changed lock
  invalidates the build.
- `build/new-toolchain-lock.ps1` refuses repository-local paths, overwrite,
  dirty/unpushed source, stale build evidence, and Visual Studio below the
  decision-date servicing floor.
