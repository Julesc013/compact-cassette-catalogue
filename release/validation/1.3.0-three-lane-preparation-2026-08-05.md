## Implemented contract

- `build/lanes.json` contains exactly `win-x86-net40`, `win-x64-net48`, and
  `win-arm64-net481`, all required, with the exact package names.
- Resolver ranges are closed to VS `[15.0,16.0)`, `[17.0,18.0)`, and
  `[18.0,19.0)`; compatible fallback is rejected.
- The original project retains `ToolsVersion="14.0"`, while lane builds force
  and verify `15.0`, `Current`, and `Current` respectively.
- Shared compilation is disabled; each lane writes an MSBuild binary log,
  property record, and toolchain JSON containing exact compiler/reference
  hashes, host identity, and source commit.
- Debug/Release ARM64 project and solution configurations build only the
  original application; historical installer/uninstaller projects have no
  ARM64 `Build.0` entry.
- PE validation uses a closed architecture mapping and inspects CLR CorFlags,
  framework/config, assembly/file/product version, settings parity, and runtime
  DLL count.
- Packaging emits only the three portable ZIPs and `SHA256SUMS.txt`, with five
  allow-listed entries per ZIP and fixed timestamps.
- Runtime proof is split into builder smoke and exact-hash target-machine proof.
  ARM64 target proof rejects an x64 host rather than running an emulated or
  relabelled binary.
